# 帧智汇登录与注册问题梳理

2026 年 11 月 24 日 · 审查基线为 `dev`（`acfef2aa`）及当前工作区。上一轮会话修复已在本地代码中，部署版本待核对。

## 当前结论

1. **注册后显示旧账号已在模拟接口环境复现，本地修复后的回归已通过。** 登录页曾把浏览器仍持有的旧业务会话当成注册成功后的新会话，直接进入首页，跳过新账号的 OAuth 回调。当前密码登录、短信登录、普通注册和短信补注册在有效提交时先清旧会话，再申请本次 OAuth 上下文。 [会话确认](../../src/views/LoginView.tsx#L181) · [注册回归](../../e2e/auth-routing.spec.ts#L104)
2. **旧账号提示密码不对，个案根因待确认。** 后端密码记录未变化来自现场反馈。注册和重置会去掉密码首尾空格，登录会原样提交，这种差异能造成类似现象。本地修复已按登录失败阶段给出通用提示，认证服务返回的具体错误仍会显示。那一次失败需要核对实际提交的账号、后端账号映射和返回业务码。 [登录失败处理](../../src/views/LoginView.tsx#L447) · [注册和重置提交](../../src/components/auth/AuthActionModal.tsx#L195)
3. **下一轮优先处理账号身份和凭据一致性。** 重点是会话响应能否证明当前账号、跨标签切换后页面身份是否一致、密码输入规则是否统一，以及用户已经离开页面时能否丢弃迟到结果。

## 审查范围与判定

范围覆盖 `/login`、受保护页面跳转、密码和短信登录、普通和补全注册、找回密码、设置中的修改密码、邀请码、业务会话恢复与续期、显式登出及 OAuth 回调。`P1` 表示优先影响账号身份、能否登录或用户确认，`P2` 表示具体场景的流程阻塞或误导，`P3` 表示可操作性与文案细节。优先级用于安排后续处理。

下表的「代码确认」指当前实现中可直接核实的行为。具备触发条件时的浏览器或真实服务结果，见「待验收」。真实账号注册、发短信、密码校验及部署配置均未在本轮实测。

## 会话、回跳与登出

| 编号 | 优先级与状态 | 问题与影响 | 处理方向 |
| --- | --- | --- | --- |
| S1 | P1 · 代码确认 | `/session` 只检查响应是对象，随后与 `/me` 浅合并，未比对两次返回的用户 ID。登录完成时仅在会话返回完整手机号时与提交手机号核对。空对象、缺少账号标识、会话和资料账号不一致时，前端缺少充分的身份判断。 [会话组装](../../src/api/auth.ts#L282) · [登录后核对](../../src/views/LoginView.tsx#L194) | 约定业务会话必备的稳定用户标识，并用它校验资料归属。用空会话、缺手机号和两个请求身份不同的模拟响应验证行为。 |
| S2 | P1 · 代码确认 | 页面卸载时会取消已经开始的桥接，但凭据请求仍在途时，迟到成功仍能重新启动一个桥接流程。用户已返回开屏或去了其他页面，也可能被带回首页。 [登录提交](../../src/views/LoginView.tsx#L434) · [卸载清理](../../src/views/LoginView.tsx#L511) · [桥接开始](../../src/views/LoginView.tsx#L181) | 从提交开始跟踪同一次尝试，离开页面或新尝试启动后废弃旧结果。验证延迟回包后点返回。 |
| S3 | P1 · 代码确认 | 凭据接口成功后就解除提交锁，业务会话还在确认期间仍可再次提交。第二次提交会先注销并取消第一轮桥接。静默桥接只在会话查询返回后检查 6 秒期限，单个慢请求会拉长等待。 [提交锁](../../src/views/LoginView.tsx#L434) · [桥接轮询](../../src/views/LoginView.tsx#L241) | 让加载状态覆盖整个提交和会话确认阶段。统一超时与可重试时机，验证慢响应和连续点击。 |
| S4 | P1 · 多标签待联调 | 注册和登录前清旧会话只处理业务 Cookie 与本地标记，显式登出另外走跨标签事件和缓存清理。浏览器标签共用 Cookie，旧标签的界面和缓存可能继续显示 A，而请求已使用 B 的 Cookie。 [提交前清理](../../src/api/auth.ts#L186) · [主动登出和跨标签清理](../../src/auth/AuthContext.tsx#L330) · [自动续期](../../src/auth/AuthContext.tsx#L182) | 用同一浏览器的两个标签验身份、工作空间、列表和草稿。再明确账号切换的跨标签通知及缓存失效时机。 |
| S5 | P2 · 代码确认，回跳待验 | 受保护页通过路由状态带入原地址。常规登录成功可回原页；静默桥接受阻、走整页 OAuth 跳转时，初始化目标固定 `/home`，原路由状态无法沿整页跳转传递。已经使用中的会话过期会复用登出清理并去开屏，原深链也可能中断。 [路由守卫](../../src/App.tsx#L170) · [OAuth 回跳](../../src/views/LoginView.tsx#L165) · [整页回退](../../src/views/LoginView.tsx#L270) · [过期清理](../../src/auth/AuthContext.tsx#L258) | 在受控的同源回跳机制中延续已校验的原页面地址，验证带查询参数的画布和项目链接。 |
| S6 | P2 · 代码确认，接口包装及浏览器兼容待验 | 提交前清理会识别 HTTP 401、`UNAUTHORIZED`、`10101`。主动登出的失败分支只认 HTTP 401。同一个未登录业务结果若使用 HTTP 200 包装，两处处理会不同。缺少 Web Locks 的浏览器中，共享续期与登出也缺少请求排序。 [清理判断](../../src/api/auth.ts#L362) · [退出判断](../../src/utils/workflowGuards.ts#L10) · [共享续期](../../src/api/sessionRefresh.ts#L39) | 核对真实返回格式，统一注销临界区和错误判定。分别验证在途续期、会话已经过期和服务端 5xx。 |
| S7 | P2 · 代码确认及契约待验 | 通用错误解析只将非零数字 `code` 或非 `OK` 的 `code_string` 识别为业务失败。若 HTTP 200 只有数字字符串 `code`，失败可能被当作成功。凭据失败已解析 `request_id`，现有诊断集中在 OAuth 桥接，定位一次实际登录失败的链路比较困难。 [错误与请求 ID](../../src/api/auth.ts#L461) · [业务码解析](../../src/api/auth.ts#L493) · [桥接诊断](../../src/views/LoginView.tsx#L65) | 确认真实状态码和业务码格式，按阶段留可用于关联排查的安全字段。 |
| S8 | P3 · 代码确认，部署待核对 | 本地会话标记与服务端 Cookie 可处于不同状态。无标记时应用可先显示访客，即使 Cookie 仍有效。OAuth 无导航地址的失败分支也会保留期待会话标记。Vite 的业务、DeepAuth、SSO 地址可分别配置，单凭本地代理代码和测试不能判断部署是否指向同一环境。 [会话探测条件](../../src/api/auth.ts#L256) · [桥接失败](../../src/views/LoginView.tsx#L216) · [环境配置](../../vite.config.ts#L17) | 核对部署的认证目标、Cookie 作用域、导航回调和本地标记的清理时机。 |
