# 无限画布免登录分享：素材访问契约

当前公开接口 `GET /api/v1/canvas-shares/{token}` 和 `GET /api/v1/canvas-shares/{token}/elements` 已能匿名读取画布结构；但节点持久化的 `resultUrl` 通常是需要工作空间登录态的 `/api/v1/assets/{id}/download?workspace_id=...`。只公开元素、不公开其引用的素材，会使分享页出现破图和无法播放的视频。

## 后端需要提供

在公开的 `elements` 响应中，为每个有素材的节点的 `payload.data` 追加只读、**不持久化**的地址：

- `publicResultUrl`：当前图片或视频素材的匿名可访问地址。
- `publicPosterUrl`：视频封面素材存在时的匿名可访问地址。

前端分享页已优先使用这两个字段，并兼容蛇形字段名 `public_result_url`、`public_poster_url`。历史元素没有这些字段时仍回退到 `resultUrl`，但后者不能保证匿名可用。视频剪辑节点若有合成成片，也应提供 `publicResultUrl`。

推荐由后端提供分享口令受控的同源流式下载地址，而不是把有较长有效期的对象存储签名 URL 写进画布元素。访问时应重新校验：分享口令有效、分享未关闭、素材确实被该画布的活跃节点或其封面/片段引用。普通素材下载接口的权限不能放宽；分享口令也不能变成整个工作空间素材的通行证。

视频流需要支持浏览器的 `Range` 请求及 `206 Partial Content`，否则拖动进度、元数据加载可能失败。跨域地址还需正确设置 CORS，并避免通过 `Referer` 泄露分享口令。

## 联调验收

1. 未登录访客打开分享链接，文字、图片、视频与连线全部可见；视频可播放和拖动。
2. 未登录访客直接请求原 `/api/v1/assets/{id}/download` 仍被拒绝。
3. 分享关闭或过期后，公开元素与公开素材地址都失效。
4. 口令不能访问不属于该分享画布的素材。
5. 分享页长时间打开后，重新播放/拖动视频仍可用（若采用短效签名地址，需要可刷新）。
