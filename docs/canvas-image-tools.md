# 无限画布：多角度、打光、全景

## 2026-10-21 整体优化

延续现有画布样式，以用户提出的 LibTV 空间控制体验为目标；已查看官方站点 https://www.liblib.tv/，没有登录到其具体工具页，不能声称逐项复刻或已经验证同等生成质量。

- 多角度增加正面、左右、背面机位，以及远中近景、仰平俯拍预设；支持拖动、滚轮景别和键盘微调。补充主体身份、场景连续性约束，避免将裁切或镜像误当作机位变化。
- 手动打光增加连续 0–360° 水平角、-89–89° 俯仰角、光位球与环绕轨迹、颜色选择、轮廓光示意；滚轮调亮度、方向键微调。手动/智能/参考模式仍使用真实后端目录与显隐规则。
- 全景生成补充完整 ERP、左右无缝、天顶与地面填充、避免鱼眼/黑边/重复主体的约束；模型 schema 明确提供 2:1 档位或尺寸格式时才设置对应参数，不跨供应商强塞 size/ratio。
- 全景产物在画廊增加沉浸取景入口，节点工具条的「全景」默认进入浏览。普通照片维持原入口。明显黑角/透明遮幅提示可能投影不正确，但不凭像素启发式直接拒绝暗场。
- 全景取景增加大屏预览和 Esc 退出、滚轮视野、键盘角度调整；横屏 1920×1080、竖屏 1080×1920、方形 1536×1536，预览画幅和真实导出相同。导出独立调整渲染缓冲后恢复预览，不再按小面板像素截图。

### 后端能力与后续原生接入

本次重新读取线上 Swagger，`image.relight` 仍为 v1，只支持六向 `key_light`。因此前端保留合法基础方向，将连续角度转换为补充提示词，与工具参数一起用于估价和提交；`light_azimuth/light_elevation` 是本地控制值，不伪造成当前接口支持的字段。当前生成引擎仍属于 prompt_workflow，精确光影和全景几何质量没有原生渲染保证。

若后端升级到原生连续布光，建议通过工具目录返回新 version 与 `light_azimuth/light_elevation` 数字 schema（水平 0..360、俯仰 -89..89），并连接真实重打光工作流；前端已有按目录版本发送和 schema 字段过滤，可发送后端明确声明的新字段。服务端还需验证模式参数隔离、素材顺序、幂等、估价与实际计费一致。

全景要达到稳定的无缝输出，需要后端接入专用等距柱状生成/扩图与接缝处理流程，返回真实宽高、projection 和素材 ID，并在发布成功前校验投影及输出尺寸。仅靠通用图生图提示词、2:1 宽高比或前端拉伸无法保证生成合格的 360° 环境；本次没有伪装已有这个后端能力。

接口核对日期：2026-10-20。使用项目当前配置业务服务的 Swagger，精简原始说明见 `artifacts/canvas-tools-contract.json`。

## 使用

选中已有图片，点击节点工具条的「多角度」「打光」「全景」。工具弹窗可切换生成和「全景浏览／取景」。工具目录不提供的能力不可选；模型列表为空时禁止生成，显示当前空间暂无可用模型。

- 多角度：拖动三维界面调整蓝色相机标记，或直接输入水平角、俯仰角、远近。三维界面为相机示意，图片生成结果由后端模型决定。
- 打光：参数、枚举、范围与模式显隐来自工具 schema。手动模式有灯位示意；智能模式使用后端预设／补充描述；参考模式必须从画布选择另一张不同图片，原图在前、打光参考图在后。
- 全景生成：创建独立结果节点，保留原图及来源连线；随后可对结果打开全景浏览。
- 全景浏览：使用 Three.js 浏览 2:1 等距柱状全景图，调整水平视角、俯仰、视野；视角写入原节点 `panoramaView`。取景通过已有素材上传链路入库，在画布添加独立图片和血缘边，不创建 AI 任务。

## 接口与真实能力边界

1. `GET /api/v1/ai/tools?workspace_id=…` 提供工具代码、版本、执行类型、参数 schema、可用模型 ID。
2. `GET /api/v1/ai/models` 提供空间可用模型与原生参数。可选模型取两个目录的交集，前端不写死模型 ID 或价格。
3. 生成调用工具目录给出的 `operation_code`（当前为 `image.image_to_image`）。`params.tool`、`params.tool_version`、`params.tool_params` 标识工具。隐藏参数和其他模式参数不传。
4. `POST /api/v1/ai/tasks/estimate-cost` 与正式提交共用同一份模型、提示词、参数和素材快照。只有有效且可支付的当前报价可生成；参数改变立即阻断旧报价，过时估价响应被丢弃。
5. `POST /api/v1/ai/tasks` 复用画布已有提交链路：幂等键、防重复、素材预检、失败提示、任务状态、刷新恢复以及 outputs 素材验证与回填。

后端当前提供的是 `prompt_workflow`，将工具参数转换为图像编辑提示词。多角度 v2 显式传 `tool_version:2`，使用目录允许的 Qwen 模型；当前接口没有声明 fal Multiple-Angles LoRA 或 IC-Light 原生推理能力，前端不会假称已经接入它们，也不会直接连接第三方供应商。

全景浏览是本地操作，不调用估价和任务创建接口。取景上传仍由素材服务鉴权并处理存储，前端不保存临时签名 URL。

## 验证

- `tests/unit/canvasTools.test.ts`：工具请求、版本、模式显隐、素材顺序、参数校验、视角序列化。
- `tests/component/CanvasImageTools.test.tsx`：估价与提交一致、参数变更旧报价失效、无模型／积分不足拦截、浏览器工具不下单。
- `e2e/canvas-image-tools.spec.ts`：生产构建上的三维预览、工具切换、生成任务与新节点回填；全景浏览、取景上传和视角持久化。浏览器测试拦截业务接口，不消耗真实积分。

在线已读取 Swagger；未登录的工具目录返回 `UNAUTHORIZED`。实际空间的模型启用、套餐授权与付费生成效果仍需在已登录环境验收。

Three.js 核心和渲染器均只在打开图片工具时加载，分别分块，避免循环依赖并保持单 JS 460 KiB 上限。完整产品面当前实测约 1248 KiB gzip，总预算随本批画布功能调整至 1280 KiB；首屏加载边界和环境泄漏检查保持不变。


## 2026-10-21 紧凑工具与全景取景

- 多角度、打光、全景按节点入口直接打开对应无蒙层浮窗；删除重复的大图模拟和重复方向预设，低频模型参数使用目录默认值，不再展示高级设置，保留原有服务端目录和估价/下单正文一致性。
- 打光模式与主光源改为按钮，智能模式提供六种可编辑的文字光效预设；这些预设调用现有模型生成，不保证原生物理布光。
- 全景浏览支持平视、仰视、俯视、广角、特写构图，以及九宫格、中心十字、安全框参考线。参考线仅叠加在界面，不进入导出图片。
- 当前视角、四视角（相对当前朝向每 90°）、十二视角（四方向 × -35°/0°/35°）直接从同一全景球面导出，无 AI 下单。默认全选预览截图，允许逐张取消、下载或上传为画布节点；已保存图片不可重复提交，失败后仅重试未保存部分。
- 取景素材通过现有上传链路持久化，各截图保存自己的 yaw/pitch/fov 与画幅。原全景图保持不变。全景必须是适合球面浏览的等距柱状图，前端不重建隐藏空间。


### 紧凑面板布局更新

多角度与打光使用独立紧凑布局：顶部预设，左侧球体，右侧模型和核心参数，底部仅重置、预估金额、生成。移除常驻说明、费用说明、重复重置以及高级设置；智能打光描述与参考图仅在对应模式展示。错误和余额不足提示按需出现，仍使用同一估价和任务正文。

打开图片工具时临时卸载原节点生成面板，关闭后恢复；提示词及生成参数仍保存在节点。工具按所选源节点的屏幕底边居中定位，保持 12px 间距，随画布移动、缩放和节点拖动同步。打开时依据面板实测高度调整视野，为图片与操作区留出空间。
