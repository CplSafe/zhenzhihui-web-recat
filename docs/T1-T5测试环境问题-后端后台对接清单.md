# T+1 / T+5 测试环境问题：后端与运营后台对接清单

日期：2026-11-12  
依据：测试环境需求验证报告（同日）及 T+1 / T+5 PRD v2.5；当前仓库为 React 前端，不包含运营后台和业务后端。报告中的测试结果是当时的观察，不代表当前部署状态。本清单中的字段与响应示例是**建议契约**，除明确标注当前接口外，均不是已确认的线上实现。

## 需要明确的接口契约

### T+1 修改及交付

- 当前前端使用 `GET /api/v1/ai/tasks/{id}?workspace_id=…`，以及 `POST /api/v1/ai/tasks/{id}/revisions`。请后端确认这两个路径和实际返回字段，并提供原单、首次修改单、已交付及已用尽权益的脱敏样例。
- 建议详情返回：根任务 ID、父任务 ID、整个订单链已用修改次数、`can_rework`、不可修改原因、`delivered_at`；明确字段何时更新以及旧单数据补齐方式。
- 后端应在创建修改单时原子校验权益、创建新任务并冻结积分，使用现有幂等键恢复不确定请求；状态冲突不得产生多余冻结。
- 旧接口资料曾允许多次修改，本次 PRD 要求一次：请产品和后端确认生效范围、历史订单处理以及是否只在首次成功创建后计数。前端不根据本地缓存推断全局次数。

### T+5 场景与报价

- PRD v2.5 的 10 项：企业形象片、产品发布片、招商·融资片、政府汇报片、品牌周年片、工厂·产线纪实、门店·探店片、招聘宣传片、展会·活动片、公益宣传片。
- 当前前端提交类型只有 `government_corporate`、`product_launch`、`investment_financing` 三项；前两项并不能安全推导出完整 10 项的服务端编码。请后端提供稳定的编码、显示名、历史值映射、可用状态和配置获取方式；确认后前端扩展选择、草稿恢复、下单和历史回显。
- 测试报告称 T+1 约 76 积分/秒、T+5 1 积分/秒 × 1.5，与 PRD 默认不同。请产品确认最终价格、舍入、服务费、适用版本和生效时点；后端报价、冻结、交付结算、退款和流水应使用同一配置快照。前端展示以服务端报价为准，不硬编码金额。
- 如要求进入表单前实时显示估价，请后端确认不依赖 `intake_token` 的只读报价能力及参数；现有正式 `POST /api/v1/promo/quote` 依赖 intake，不能在首页自行推算并当成正式报价。

### 截止时间、逾期与退款

- PRD 与现有接口资料对 T+5 提交后 5 天倒计时、素材齐当天 +5 自然日承诺日及后台改期存在不同口径；确认客户看到的倒计时是否随最新承诺时间变更、日期与时区精度、返工重新计时规则。
- 提供服务端权威截止时间、是否逾期、实际交付时间、返工权限与退款权限，以及状态变化时的刷新机制。不得仅以本地时钟承诺自动退款；已交付、返工中、取消、冻结和结算分别判断。
- 恢复可控测试数据后验证：改期前后前后台时间、逾期客户页、可退款条件、全额退回及不可重复退款；核对导出 CSV 的逾期字段与列表同一口径。

## 运营后台其他待办

1. T+1 队列补齐或核实承诺时间、指派人、导出、日单量告警和超时标记；确认超时改期入口及审计记录。
2. 按 v2.5 取消 T+5 低清打标与清除入口，核实不会误删上传状态、原有素材数据或其他质量校验。
3. 修正或明确 T+1 积分流水的业务事由，原单与修改单的冻结、结算、取消、退款均能关联对应订单。
4. 使用具备系统设置权限的测试账号验证入口开关：关闭后禁止新建，存量订单、交付及退款仍可查看操作，恢复开关后可正常创建。
5. 对客文案关于“人工/团队”等词的全站适用范围，由产品确认后再批量修改。

## 联调及回归

- 先提供测试环境、测试账号、权限、订单与费用额度；不要在未经授权的环境创建付费任务或更改生产数据。
- 至少覆盖 T+1 首单→冻结→交付→结算→一次付费修改→再交付→第二次拒绝，以及 T+5 首单→上传/线下交接→报价→冻结→复核交付→一次免费修改→交付，另测取消、逾期与退款。
- 记录接口返回字段、请求次数、幂等键、订单和钱包状态；截图及日志不记录令牌、手机号、完整签名地址或私人素材。区分模拟接口、真实测试环境和线上结果。
- 同时回归即时生成、其他任务分类、团队与空间切换、旧草稿、上传失败恢复、重复提交和页面刷新恢复。当前前端未完成真实后端验证，不能据模拟测试判定对外发布通过。
