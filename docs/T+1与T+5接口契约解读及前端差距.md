# T+1 与 T+5 接口契约解读及前端差距

> 分析日期：2026-11-04。依据：用户提供的 `ai-t1-t5-integration.md`（version 1，后端 source_commit `2b07e4c`）以及当前工作区代码，包括尚未提交的改动。本文是接入分析，不代表已验证后端部署版本，也不代表功能已上线。原文中的开发 AI 指令在本文中作为待分析的接口约束，不作为本次工作指令。

## 一、结论

当前 T+1 精制成片和 T+5 定制宣传片均已有可交互原型，但核心任务、费用、交付及修改状态主要来自浏览器本地演示数据，尚不能视作真实业务接入。原型明确标有演示提示，这有助于识别，但接入时必须替换模拟逻辑，不能将本地记录当成服务端订单。

新的接口文档给出了此前方案缺失的关键契约：T+1 使用通用 AI 任务和人工模型，T+5 使用宣传片订单与独立素材。两者在标识、报价、修改、取消和退款方面明显不同，需要分别建模。T+1 没有自动交付承诺及逾期退款；T+5 的日期、修改权限和退款条件以订单为准。

建议先确认产品接受现有原型与后端契约的差异，再分别实施 T+1 与 T+5，最后接入统一任务中心及项目管理。本文只整理对接方案和待确认事项，未修改业务代码。

## 二、文档逐项解读

### 2.1 两条流程的边界

| 对比项 | T+1 人工视频 | T+5 定制宣传片 |
| --- | --- | --- |
| 服务端识别 | 模型 `provider=manual-video`；已知人工任务上下文 | 订单 `order_type=promo_t5` |
| 主体 | AI 任务 `task.id` | `intake_token` 上传会话、`order.id` 订单、`order.task_id` 统一任务，不能混用 |
| 时长 | `params.duration`，15–300 整数秒，参数及选项取模型 schema | `duration_seconds`，档位取配置 |
| 报价 | 通用 estimate-cost 的 `estimated_cost` | 专用 quote 的 `base_cost`、`service_cost`、`total_cost` 和 `config_hash` |
| 输入素材 | 通用 asset，传 `asset_id` | 宣传片专用 material，使用 `material.id` |
| 计费 | 本次任务提交冻结、交付结算；失败或取消退回本次费用 | 首次提交冻结、首次交付结算；满足逾期条件可申请全额退款 |
| 修改 | 已交付人工任务可按父任务原报价付费修改，新建任务，可多次 | 同一订单内以 `can_rework` 为准申请一次免费修改 |
| 取消 | 文档指出未结束人工任务可取消；页面守卫列为 `awaiting_manual` / `manual_processing` | 客户无普通自助取消，联系顾问 |
| 日期 | 无自动承诺日、逾期状态或逾期自动退款 | 使用服务端 `promised_date`；返工承诺规则为首次交付日加 2 个自然日 |

文档区分了“返工申请窗口”和“返工承诺日”：前者是首次交付后 3 个自然日内、且服务端允许时申请；后者按首次交付日加 2 个自然日，并非从申请或受理日重算。这里存在业务上可能出现申请时已接近或超过返工承诺日的情况，应向后端和产品确认边界展示，但前端不自行改写规则。

### 2.2 T+1：从模型到交付

1. 请求视频模型目录，选择可用的 `provider=manual-video` 模型，并从其 `operation_codes` 中取相应视频操作。表单参数、默认值和分辨率等来自 `params_schema`；不能沿用 T+5 的选项或写死模型 ID。文档给出的当前初始分辨率是 480p/720p，具体以接口为准。
2. 需求写入 `prompt`，参考素材可选；按通用素材申请、对象存储直传、complete 后才引用其 `asset_id`。素材必须属于当前空间，并满足文件数量、类型、大小与通用上传限制。单次只创建一条，不能开放批量。
3. 使用相同的模型、操作、提示词、参数与素材快照调用估价，估价请求不带幂等键。展示服务端预计积分与余额、冻结额、`can_afford`；积分已是正常单位，不除以 1000，不按时长算价。修改输入后，旧报价不再用于确认。
4. 创建任务时生成一次幂等键，固定请求快照。网络超时等结果不明时，重试同一请求必须复用原键与原正文；只有明确开始新的一次操作才创建新键。成功保存任务 ID，刷新钱包。
5. 查询任务详情，以 `poll_after_ms` 决定下一次查询；为 0 时停止，页面离开停止。待制作、制作中、已交付、失败和取消均按服务端状态展示，不生成虚构进度。完成或失败后更新钱包。
6. 已交付时从 `outputs` 找 `type=video`。有 asset ID 则取短期下载地址、过期重新获取；只有 URL 时可播放或打开。不要把签名地址当长期资产身份保存。
7. 仅在**已知人工任务上下文且状态为 succeeded**时开放修改；以父任务 `estimated_cost` 做付费确认，提交 `instruction` 和新操作的幂等键。返回的新任务独立轮询和计费，保留原结果，下一次修改指向最近一次已交付任务。失败或取消只退当前任务费用。
8. 人工任务处于允许状态时，可二次确认后调用取消；结果以服务端为准并刷新任务与钱包。不得展示次日 18:00 承诺、自动逾期退款或专属人工任务历史筛选。

### 2.3 T+5：从配置到订单

1. `GET /promo/config` 决定入口、名称、时长、比例、分辨率、素材限制、客服及授权文本。`enabled=false` 关闭新建入口，但保留历史查看。配置具体结构以真实响应为准。
2. 创建 intake，保存 token；此时没有订单、没有扣费。素材按角色 `footage`、`logo`、`supplement` 申请凭证；`form_fields` 原样加入表单、最后追加文件，再 POST 到返回的存储 URL。存储请求不能带业务授权或 Cookie。
3. 对象存储上传成功仍需调用 complete，返回 `status=active` 才能计为有效素材。刷新可查询 intake 与 materials；凭证过期或上传失败用原 material 的 retry，文件已上传而 complete 失败则先重试 complete；多余或失败项可在下单前删除。pending 项不能遗留到提交，最低实拍数量或允许的线下交接由配置控制。低清晰度只提示；无法读取尺寸不拦截。
4. 用 token、时长、比例、分辨率请求 quote，展示各项费用、`total_cost`、`promised_date`，保留 `config_hash`。规格变化要重新报价；`price_show=false` 或 `manual_quote_required=true` 时联系顾问，不能绕过核价。
5. 收集公司、联系人、电话、场景、旁白、需求及可选参考链接，并以 config 提供的两份声明及版本完成确认。场景和旁白提交契约枚举，不传原型中的展示文案。下单请求使用报价 hash、同一次操作稳定的幂等键和正文快照；结果不明确时保持该快照重试，成功后保存 order ID 与 task ID 并刷新钱包。
6. 列表返回订单集合和 `has_unfinished`，已有未完成订单仅提醒，不禁止继续。详情返回 `{order, materials}`：制作状态和计费状态分开显示，逾期判断优先看 `is_overdue`；日期直接使用 `promised_date`，不能把截止次日零点 `due_at` 当交付日期。订单进行中等需要更新的状态可 30–60 秒查询一次，离开停止。
7. `delivered_material_id` 有值时从宣传片素材下载接口取短期地址并支持过期重取。修改入口完全依据 `can_rework`；提交 `text`，显示 requested/accepted/rejected/fulfilled 及回复，不新建付费任务。
8. 仅当 `is_overdue=true`、`first_delivered_at` 为空且 `billing_status=frozen` 同时成立时，展示二次确认后的退款操作；请求 `{confirmed:true}`，成功刷新订单与钱包。已交付返工逾期不可退原费用，也不提供普通自助取消。

### 2.4 通用约束

业务响应按统一封装处理：`code=0` 成功，失败展示后端 `message`；401、402、403/404、409、503 应保留明确的登录、余额、权限、状态冲突和重试反馈。所有页面需要加载、空态、失败重试、提交防重和离开时取消请求/轮询；不能模拟交付或虚构百分比。对象存储直传需要单独处理凭证、跳转与域名安全，业务请求继续复用项目登录态与错误处理。

## 四、建议实施清单

### P0：上线前必须完成

- **领域与接口**：分别定义人工任务、宣传片配置/素材/报价/订单及接口客户端；严格区分 ID、任务状态、订单状态和资金状态。复用业务请求封装、登录态、钱包刷新；根据后端完整响应补齐类型。
- **T+1**：人工模型发现、schema 参数、真实资产引用、估价与余额、稳定幂等创建、0 停止轮询、交付播放下载、原价付费修改、新任务链、取消及退款状态。移除真实流程里的固定报价、明日交付、自动退款、假进度与模拟成功。
- **T+5**：配置开关及全部配置驱动表单；intake 恢复、直传/complete/retry/delete、线下交接、报价和 hash、声明确认、稳定幂等下单、订单详情和列表、轮询、交付播放、免费返工和条件退款。订单提交前阻止未完成素材、无授权、报价过期等非法状态。
- **恢复与隔离**：提交结果未明确前保留原请求及键，并按账号、工作空间隔离；避免在重试时重新生成键或悄悄变更请求。明确退出、刷新、切换空间和登录过期时如何恢复，确保敏感信息及短期 URL 不被长期保存。
- **入口与历史**：任务中心和项目管理展示真实记录，识别 promo 订单后跳转订单详情。T+1 仅对有可靠人工上下文的任务提供修改；不能承诺可从混合列表完整筛出历史人工任务。明确演示数据如何保留、隐藏或清理，不能当作真实订单迁移。

### P1：联调与体验完善

- 两流程均覆盖加载、空、失败、重试、防重复、余额不足和状态变更；短期地址过期重取；状态变化刷新钱包；权限异常给出后端错误。
- 对移动端、键盘及读屏、文件错误、上传中断、页面离开与返回、登录过期、多设备及切空间进行验证。
- 文档提供的成功闭环全部联调：T+1 下单、后台交付、播放下载、付费修改和失败或取消退款；T+5 上传、报价、下单、后台交付、播放下载、免费返工及逾期退款。分别记录 mock 与真实后端结果。

## 五、需要产品及后端确认的问题

1. **T+1 产品定位**：现有原型名为“精制成片”，含脚本、验收、次日 18:00 和超时退款；新契约是人工视频任务，尚无验收、自动承诺或逾期退款。是否以新契约调整产品文案与步骤？脚本如何拼入 `prompt`，是否需要额外后端字段？
2. **T+1 历史识别**：任务回包缺少可靠的人工业务标记，如何跨设备识别所有已交付人工任务并开放修改？需要后端提供 provider/业务标记或明确的列表能力；在此之前只能处理已知上下文，不能声称历史完整。
3. **模型与参数细节**：请提供实际模型目录和 `params_schema` 样例、操作码、支持的素材角色及参数校验细节；15–300 是整数范围，UI 如何提供输入由产品决定。
4. **T+5 配置与权限**：提供 config、quote、intake、material、订单详情和错误响应完整样例，尤其配置字段结构、客服电话、授权文案、账户及空间隔离、分页与线下交接条件。文档没有给出所有嵌套字段，不应猜测。
5. **T+5 报价和不确定提交**：确认 `config_hash` 失效/价格调整响应、重试与冲突处理；请求结果不明期间用户编辑需求或切换设备时，如何查询或安全恢复原提交，不能在未知结果时直接当成一笔新订单。
6. **日期边界**：确认三自然日窗口的起止时刻、时区及“首次交付日 + 2 自然日”可能早于申请/受理时间时的展示，均以服务端字段和 `can_rework` 为准。
7. **环境联调**：确认部署是否包含该快照、模型可见性与价格开关、测试账号和空间权限、对象存储 CORS、可用测试素材，以及后台制作/交付和退款测试方式。
