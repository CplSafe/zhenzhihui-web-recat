# 前端修改后的浏览器验证规范

适用于页面、样式、组件交互、路由、权限以及异步生成任务状态的修改。仅文档或不影响用户行为的修改无需启动浏览器。目标是验证用户能完成操作，并检查失败与恢复场景。

## 1. 修改前确定验收范围

- 列出受影响的路由、入口、用户身份、操作步骤和可观察结果。
- 先复现问题；无法复现时注明条件，避免将推测当作根因。
- 查看现有 `e2e/` 用例，优先复用或扩展相关流程。按风险补充回归，不为纯样式微调堆叠重复单测。
- 第三方库行为不确定时，用已连接的 Context7 查询与项目实际安装版本匹配的文档；不可照搬最新大版本 API。
- 大幅调整用户流程时，可使用已安装的 Product Design 评审方案；实现仍遵循项目既有 Ant Design、样式和组件规范，不擅自更换技术栈。

## 2. 检查与执行顺序

1. 运行 `npm run typecheck`，对修改文件运行 ESLint、Prettier 检查；涉及测试代码时运行对应的测试类型检查。
2. 对逻辑修改运行相关 Vitest 测试。新增关键业务回归时，按项目规范检查 `vitest.config.ts` 的覆盖率白名单。
3. 构建当前工作区，并运行受影响的生产预览 Playwright 用例，至少覆盖 Chromium。
4. 在浏览器中打开修改页面，实际执行操作并检查最终画面。自动化可完成此步骤，但必须检查截图、页面状态和实际操作结果，不能只读取测试退出码。
5. 涉及真实接口、生成任务或草稿保存时，再进行真实后端验证；明确测试环境、账号和数据范围。
6. 修复失败后重跑失败场景及受影响的相邻流程。不得通过跳过用例、降低断言或无依据更新截图基线来获得通过。

以下为现有命令示例，文件名按本次修改选择：

```sh
npm run typecheck
npm run test:typecheck
npm run test:e2e:typecheck
npx vitest run tests/unit/canvasUpscaleDisplay.test.ts

# 此脚本先构建，再运行指定 Chromium 用例
npm run test:e2e -- e2e/canvas-upscale-panel.spec.ts

# 补充浏览器验证前先确保 dist 对应当前源码
npm run build
npx playwright test e2e/canvas-upscale-panel.spec.ts --project=webkit

# 移动项目只匹配 mobile.smoke.spec.ts，不能用任意桌面用例替代
npm run test:e2e:mobile
npx playwright show-report
```

Windows 如遇 PowerShell 的 npm 包装脚本异常，可使用 `npm.cmd` / `npx.cmd` 或 `cmd /c npm ...`，确认命令确实产生检查输出。

`playwright.config.ts` 使用 `127.0.0.1:4173` 的生产预览，自动启动独立服务且不复用已有服务。不要将其改为复用未知开发服务；端口冲突时先确认占用者，不擅自结束用户进程。真实后端验证使用项目现有 Vite 开发代理及测试环境配置，不能把生产预览测试通过当作真实代理联调通过。

## 3. 按修改类型选择场景

| 修改类型 | 必验场景 | 扩展范围 |
| --- | --- | --- |
| 页面和布局 | 主入口、内容溢出、按钮遮挡、弹窗层级、实际截图 | 至少桌面与窄屏各检查一次；涉及媒体或兼容性时补 WebKit |
| 表单和弹窗 | 有效输入、无效输入、提交反馈、重复点击、关闭与重开 | Tab 焦点、Enter、Escape 按实际产品约定检查 |
| 路由和权限 | 页内导航、直接访问、刷新、返回、访客和登录用户 | 涉及权限时覆盖允许与拒绝，参考 auth-routing / authenticated-routes |
| 异步任务 | 提交中、排队、处理中、成功、失败、查询异常、恢复 | 检查请求参数和次数，不能仅检查 loading 文案 |
| 草稿与会话 | 保存、刷新恢复、切换项目和工作区 | 检查旧请求不会覆盖新会话，参考 workspace-switch-isolation / smart-entry-reset |
| 画布 | 选择、拖拽、连线、工具面板与修改功能 | 验证删除、撤销、快捷键与输入框不会互相干扰 |

只测试与修改有关的场景；共享布局、路由、权限或任务基础设施修改需扩大到相关页面。CI 的完整多浏览器检查仍按现有工作流执行。

## 4. 生成任务与并发的专项要求

- 连续点击与不同入口触发时，检查实际任务创建请求数量、模型、素材和工作区参数。
- 同模型视频超分：已有任务提交中、排队或处理中时，应拦截新提交；终态后可重试。覆盖尚未返回任务 ID 的窗口。
- 刷新或断网恢复后，应关联已有任务；状态不确定时不得静默创建新任务或更换幂等键重试。
- 检查 409、超时、余额不足等反馈，以及输入、素材和重试入口是否保留。
- 核对任务成功后结果可预览，刷新后可重新解析素材；不将签名 URL 当作永久地址。
- 当前页面内的并发拦截不能作为跨页面、跨用户或服务端并发保证，报告必须注明实际范围。

## 5. 模拟接口与真实后端必须分开

Playwright 中的 `page.route` 和 `installStrictAuthenticatedApp` 属于模拟接口验证，适合稳定复现状态和竞态。优先复用严格 fixture，检查意外请求、写入次数及工作区隔离，避免用统一成功响应掩盖接口错误。

真实后端验证检查接口契约、权限、素材访问、保存恢复及任务链路。先执行已授权的可逆操作；只有已获授权的测试账号、素材和费用范围内才提交付费生成，不因“验证”擅自产生费用或修改生产数据。未获得所需账号或费用授权时继续完成模拟验证，并注明真实生成未验证及原因。

浏览器操作工具不可用时，可运行仓库 Playwright；无法执行浏览器时，不把类型检查或组件测试替代为浏览器验收。真实联调受阻时也不能将模拟结果标记为真实成功。

## 6. 浏览器检查与证据

- 检查未捕获页面异常、控制台错误、失败网络请求；区分预期错误场景与新增异常，不隐藏全部日志。
- 使用可访问角色、名称和稳定标识定位；等待 UI 或请求的可观察状态，避免固定 sleep。先安装监听和网络拦截，再执行操作。
- 截图检查加载完成后的关键状态；纯截图不能证明提交成功，请结合请求和界面断言。
- 现有失败证据保存在 `test-results/` 和 `playwright-report/`，配置已保留失败截图、视频及 trace。
- 如需额外验收截图，放在 `test-results/`；证据和报告不包含令牌、密码、完整签名 URL 或私人素材。不得提交浏览器登录状态文件。

## 7. 完成交付必须说明

交付时简明报告以下内容，不要求为每次修改创建报告文件：

```text
变更：受影响页面与用户可感知的变化。
已验证：实际命令、浏览器、视口、操作及结果。
接口环境：模拟 / 真实后端，真实任务是否实际提交和完成。
证据：截图、报告或 trace 的本地路径（如有）。
未验证：范围、原因及仍需满足的条件；无则写无。
```

“通过单测”“请求已提交”“真实任务已完成”是不同结论，只报告已观察到的结果。新发现的阻断问题应修复并复验，或明确标为未完成，不能声称全部验证通过。

## 8. 本机 Hooks 与验收记录

本项目已配置 `.codex/hooks.json` 的 SessionStart、PreToolUse、PostToolUse、Stop 四个事件，脚本为 `scripts/hooks/frontend-gate.mjs`。只作用于本仓库，不影响其他项目；不会自动提交付费生成任务，也不会在每次点击后运行全量测试。

- SessionStart：加载验收要求，保存会话开始时的代码快照；恢复和压缩上下文不会重置快照。
- PreToolUse / PostToolUse：对比代码内容，发现本会话产生前端修改时提醒必须验证。直接 shell 写文件也通过内容变化识别，不依赖编辑工具名称。
- Stop：前端有修改但缺少当前内容的成功测试与截图复核记录时，返回阻断原因，要求继续验证或如实交付未通过状态。

脚本兼容 Windows 盘符大小写和 `\\?\` 长路径前缀。实际命令入口会在 `.codex/frontend-verification/runtime-events.jsonl` 记录事件名、时间、会话 ID、工具调用 ID、目录匹配结果和进程号，不记录用户消息、工具参数或环境变量。导入脚本的单元测试不会生成此事件日志。诊断时必须按会话 ID 区分记录，不能把其他聊天的事件或手动执行脚本的结果当作当前聊天的自动触发证据。

使用入口（Windows 请用 `node.exe`，避免 PATH 中同名空文件遮蔽 Node）：

```sh
# 选择与改动相关的实际用例，可同时传多个文件
node.exe scripts/hooks/frontend-gate.mjs verify e2e/canvas-upscale-panel.spec.ts

# 根据 verify 输出路径查看实际截图，并检查用例中执行的交互与断言
# 再登记具体复核结论；不要未看截图就执行
node.exe scripts/hooks/frontend-gate.mjs review <run-id> "已查看超分面板截图；检查关闭重开与原文恢复，未出现遮挡"

# Hooks 自测，不需要浏览器
node.exe --test scripts/hooks/frontend-gate.test.mjs
```

`verify` 会先构建，再使用现有生产预览配置运行 Chromium；独立服务默认端口为 4273（可通过 `FRONTEND_VERIFY_PORT` 设置），不复用现有服务。禁用重试、禁止 test.only，拒绝零用例、跳过、预期失败或失败结果，并为通过用例保存最终截图。产物放在 `test-results/frontend-gate/<run-id>/`，本地记录放在 `.codex/frontend-verification/`，均不入库。当前命令仅提供 Chromium 的机器验收入口；WebKit 和移动端仍按前述规范补验并报告。

代码、素材、测试、构建配置、依赖或环境文件内容变化后，记录失效；报告和截图缺失或内容改变也失效。脚本保存环境文件摘要，不保存环境文件明文。不要手工编造或修改验收记录。

验证无法通过时，最终消息必须以 `验收状态：未通过` 开头，列出失败或未验证范围、原因与下一步，不能同时声称“已完成”“全部通过”。允许如实结束受阻任务，以免断网或缺少账号时无限重试；未通过的代码仍会在后续会话回合继续要求验收。

### 启用与边界

官方要求非托管 Hooks 经用户审核并信任当前定义才运行。重新打开本仓库的 Codex 会话后，通过 `/hooks` 检查并信任这四个 Hook；定义改变需要重新审核。项目 `.codex/config.toml` 已开启 hooks，不能据此认为信任步骤已完成。不要修改信任数据库或使用绕过审核参数来代替用户审核。

`.codex/` 和 `AGENTS.md` 当前被仓库忽略，因此注册配置仅本机存在；脚本和本规范可以随仓库提交。迁移机器时需重新创建注册配置并审核。

Hooks 是工作流检查，不是不可绕过的安全边界：用例是否覆盖本次修改、截图是否实际被查看、真实后端是否成功仍需据实判断。复核文字是操作者的显式声明，脚本不能读取人的视觉判断，也不能证明模型生成成功。已有其他会话修改会作为初始基线保留，不能用本次验收声称它们全部通过。

官方配置说明：[Codex Hooks](https://learn.chatgpt.com/docs/hooks)。
