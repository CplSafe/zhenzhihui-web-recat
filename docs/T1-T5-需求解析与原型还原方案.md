执行顺序：用户本次及此前明确决定 > PRD 的后续修订 > PRD 旧段落 > HTML 中的演示数据。HTML 用来还原布局与交互，不把假数据、模拟按钮、写死的价格和假订单当成真实接口结果。PRD 中 v2.5 更新的 T+5 取消低清提示、十种场景、上下排版及 T+1 修改确认流程应覆盖较早条目。

### 已确认的覆盖规则

1. T+1 截止时间为提交时刻 +24 小时；T+5 倒计时从提交时刻起算 +5 天。展示沿用现有 `DeliveryCountdown`：T+1 ≥1 小时为 `HH:MM`，不足 1 小时为 `HH:MM:SS`；T+5 ≥1 天为 `DD天 HH`，1 小时至不足 1 天为 `HH:MM`，不足 1 小时为 `HH:MM:SS`。每秒刷新，文案“成片将于……之内完成交付”。这些明确决定覆盖 PRD v2.5 带单位的格式。
2. T+1、T+5 首次成片交付前的待制作/制作中放“正在生成”，成片反馈后进入各自成片分类；不新增独立“精制任务”页签。返工时如果已有成片，当前代码保留在对应成片分类；这是现有实现而非额外的用户确认，若要返工时回到“正在生成”，需另行明确。
3. T+5 PRD 同时写“提交时刻 +5 天倒计时”和“素材齐当天 +5 自然日承诺日、后台可改期”。现有前端前者从 `created_at` 算，后者展示 `promised_date`，不保证一致。页面需分别标明计算口径，不得把两者假装成同一个时间；最终承诺和改期规则需前后端统一。

## 2. 目标与边界

客户能以真实账号在所属空间选择产品、核对需求、取得服务端报价、提交、查看状态、播放下载及按权益申请修改。即时生成链路不应被改变。已提交订单可恢复，提交结果不确定时保留同一幂等键，不应重复扣费。制作与计费状态分别以服务端为准。

本项目为 React 18 / TypeScript / Vite，页面依赖 Zustand、React Router、Ant Design；沿用现有壳层和接口。后台派工、订单创建、定价、积分冻结/结算/退款、素材存储、成片复核、飞书通知、真实分享授权及 AIGC 标识不能由前端伪造。

## 5. 视觉还原规范

**必须读取 HTML 后段覆盖 CSS，而不是只复制开头旧样式。** 两份 HTML 都含 v2.2 视觉覆盖和后续修改；两份 PRD 的 v2.5 又明确 T+5 首页上下布局、等待页三分区。若 HTML 原始静态布局与后续修订不一致，使用后续需求，实际效果需在浏览器运行原型核验。

| 对象 | 目标 | 当前关注点 |
| --- | --- | --- |
| 站点框架 | 保留真实站点导航、登录态、任务入口；参考原型的浅灰底与内容宽度 | 不替换用户现有品牌、导航及已有生成流程。 |
| 字体/颜色 | 原型使用中文系统字体、正文深灰、弱化文字、中性边框和绿色状态强调；v2.2 主操作为深墨色 | 验收以原型最终层叠样式为准，不能把旧绿色主按钮/渐变误当最终效果。 |
| 圆角/阴影 | v2.2 小圆角、轻边框、弱阴影；确保弹窗、卡片、按钮层级一致 | 当前部分页面仍有大圆角、绿色胶囊按钮和明显渐变，需局部改为原型覆盖层。 |
| 进度/等待 | 两条链路各自显示正确阶段；等待视觉、倒计时、三分区和客服区具有清晰主次 | 保留原组件功能；不复制原型“跳到明天”等演示动作。 |
| 订单/表单 | 信息卡与订单卡按原型布局，字段、空态、校验、费用层次清晰 | 桌面优先；现有窄屏需可用，原型固定 1280/1440 宽不应造成移动端横向溢出。 |
| 交付页 | 左侧播放器、下载与交付信息，右侧修改和客服 | 视频是真实素材，图像、进度、费用不应使用原型假数据。 |
| 交互状态 | hover、focus、disabled、loading、失败、重试、已交付、退款和权限不足 | 保留键盘可达、按钮标签、屏幕阅读器状态以及减少动态效果设置。 |

## 6. 依赖后端确认的合同

1. T+5 十个场景的稳定枚举及旧值兼容；素材上传格式、域名、数量与大小限制；前置估价是否允许未完成素材。
2. T+1 测评标识、原任务参数及素材回显、`rework_count`/`can_rework`、修改申请费用和拒绝原因；按订单状态判断而非信赖本机缓存。
3. 两条订单 `created_at`、实际交付时间、时区、承诺时间和改期；T+5 倒计时与素材齐承诺日同时存在时的明确展示规则。
4. 冻结/结算/退款、逾期及修改时限由服务端执行；金额、是否可修改、退款原因由后端返回。补齐多空间订单按空间筛选分页。
5. 新单飞书通知在服务端订单创建成功后发送：分别为“收到 1 条T+1订单，详见订单 url”和“收到 1 条T+5订单，详见订单 url”；需确保幂等、失败可追踪及重试不阻塞下单。群配置和密钥不能放前端。
6. 正式成片分享权限、文件下载与 AIGC 标识由后端提供；不使用短期签名 URL 当成永久分享链接。

## 7. 分阶段实施和验收

1. **基线**：记录当前未提交修改、两个 HTML 实际渲染和桌面/窄屏截图；按现有组件检查状态、接口与影响范围。
2. **视觉还原**：分别对 T+1、T+5 的入口、表单、确认、等待、交付和错误态匹配原型最终覆盖层；保持真实导航与响应式。
3. **T+1 流程**：核对七档、模型切换、测评显示、参数与报价、幂等提交、等待、修改确认及可用权限。
4. **T+5 流程**：核对表单与素材、线下交接、正式报价、确认提交、订单各状态、播放下载及修改；场景枚举和前置报价按接口合同接入。
5. **任务与时间**：覆盖用户确认的分类与秒级倒计时边界、刷新重入、时区、跨空间和已交付/取消等状态；明确承诺日期和倒计时差异。
6. **自动化与视觉**：类型检查、修改文件 lint、业务逻辑单测；运行受影响的生产构建 Playwright 流程，检查截图及桌面/窄屏实际交互，按照 `docs/frontend-browser-verification.md` 记录 review。失败不能以截图更新或跳过用例代替修复。
7. **真实联调**：使用已授权测试账号和明确的测试订单，分开核验模型配置、上传、报价、冻结、后台接单、交付、修改、退款和飞书通知；记录数据和积分影响，区分模拟与真实结果。没有真实环境证据时明确标为未验证。
