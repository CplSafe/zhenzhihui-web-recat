# T+1 精制交付与 T+5 定制宣传片页面测试标准

适用范围：爆款成片中的 T+1 精制交付，以及 `/promo` 的 T+5 定制宣传片。包括从入口进入、填写、报价、提交、任务与订单详情、交付和相关历史入口；不要求测试其他创作流程。本文是测试标准和用例清单，不代表这些功能已经通过验收。

## 1. 执行前准备

1. 记录代码版本、测试日期、浏览器及版本、视口、接口环境、工作空间和测试账号类型。核对当前后端契约与配置；历史方案文档中的日期、价格和承诺不能当作当前服务端事实。
2. 分别准备可用与不可用的人工模型、T+5 服务开放与关闭、余额充足与不足、不同状态的任务和订单，以及两个互不共享数据的工作空间。素材使用可公开的测试文件。
3. 至少在 Chromium 的桌面（如 1440×900）和窄屏（如 390×844）检查关键页面，记录浏览器控制台异常、请求失败和截图。涉及移动兼容性时补测移动浏览器及 WebKit。
4. 先执行 mock，再执行真实后端测试并分别记录结果。真实付费生成、退款和修改须使用已授权的测试账号、素材及费用范围；没有授权时不提交，并标记未验证。
5. 不记录令牌、Cookie、私人素材或完整签名链接；不得将模拟订单或本地演示数据当作真实订单。

## 2. 通用检查

| 编号 | 检查步骤 | 通过标准 |
| --- | --- | --- |
| C01 | 从页面入口进入，再直接访问、刷新、返回 | 页面与任务上下文正确；未登录或无权限时按实际权限规则提示或引导，不泄露数据。 |
| C02 | 查看加载、空状态和接口失败 | 状态明确；错误有可执行的恢复方式；保留用户已输入内容。 |
| C03 | 快速重复点击提交、断网或超时后重试 | 不产生重复业务任务；结果未知时使用同一次请求的原快照和幂等键，不能悄然创建新操作。检查实际请求次数和正文。 |
| C04 | 切换账号或工作空间，打开历史和详情 | 仅显示当前账号和工作空间有权查看的数据；旧请求不能覆盖新空间页面。 |
| C05 | 桌面及窄屏操作各步骤 | 主要内容、提示和操作可见或可正常滚动到达；无水平溢出、遮挡、文字重叠或按钮无法点击。 |
| C06 | 使用键盘完成表单和弹窗 | 交互控件有可识别名称和可见焦点；Tab 顺序合理；弹窗可按产品约定关闭，错误与必填项能被识别。截图本身不能证明无障碍合规。 |
| C07 | 检查任务中心和项目管理入口 | 类型、状态与跳转对象正确；分页、刷新和空列表正常；演示记录与真实记录不混淆。 |

## 3. T+1 精制交付

入口：爆款成片页的视频生成模型中选择「精制交付 · T+1」，进入需求核对、报价、提交和任务详情。测试数据及选项以当前人工模型目录和服务端响应为准。

| 编号 | 测试场景与操作 | 通过标准 |
| --- | --- | --- |
| T1-01 | 打开模型选择；分别模拟可用、无模型、配置不完整和加载失败 | 可用模型可进入精制流程；不可用时说明原因并提供恢复途径，不误选普通模型。 |
| T1-02 | 输入需求和参考素材，选择模型参数 | 页面正确保留需求、素材和参数；参数与服务端 schema 一致，素材引用属于当前空间。 |
| T1-03 | 检查时长边界：14、15、300、301 秒及小数 | 在当前契约规定的 15–300 整数秒范围内可继续，其他值明确提示；其他 schema 限制也以实际返回为准。 |
| T1-04 | 请求报价；修改参数或素材后重新报价 | 展示服务端报价、余额、冻结额；变更后的提交不能使用旧报价或旧请求快照。余额不足时不能提交。 |
| T1-05 | 确认提交；分别模拟明确拒绝、超时和服务错误 | 明确拒绝显示原因；结果未知时保留请求、可安全重试；成功后显示正确任务编号和状态。 |
| T1-06 | 检查待制作、制作中、成功、失败、取消，以及查询中断和恢复 | 状态与服务端一致；按服务端轮询提示执行，`poll_after_ms=0` 时停止；离开页面停止轮询。查询失败后能明确感知并恢复，不能长期静默显示旧状态。 |
| T1-07 | 已交付任务播放、下载，模拟媒体链接过期 | 能取得并使用有效媒体地址；过期时可恢复；不把短期签名 URL 当作永久资产。 |
| T1-08 | 对允许修改的已交付任务提交修改 | 显示服务端适用费用并二次确认；修改生成独立任务，保留原结果；失败重试遵循幂等规则。未授权或不符合状态时不可修改。 |
| T1-09 | 在允许状态取消任务，并检查钱包和最终状态 | 二次确认后以服务端结果更新任务和余额；失败可见，不虚构退款或交付承诺。 |
| T1-10 | 从任务中心、项目管理及历史进入任务，刷新或切换空间 | 正确关联已知人工任务，权限和空间隔离有效；不得把普通任务误标为 T+1，也不假定混合历史能够完整识别所有人工任务。 |

## 4. T+5 定制宣传片

入口：侧边栏「定制宣传片」或 `/promo`。填写需求、上传素材、确认声明、查看报价、提交订单并进入详情；具体选项、限制和服务开放状态由配置及订单响应决定。

| 编号 | 测试场景与操作 | 通过标准 |
| --- | --- | --- |
| T5-01 | 检查服务开放、关闭、配置缺失及加载失败 | 开放时可开始；关闭时不能新建但仍能查看有权访问的历史订单；配置错误或请求失败有明确提示及重试。 |
| T5-02 | 创建需求，填写公司、联系人、电话、制作需求等，分别留空或输入异常值 | 必填校验准确、提示定位清楚；返回上一步和刷新后可恢复草稿；不把创建上传会话误称为已下单。 |
| T5-03 | 上传实拍、LOGO 和补充素材；测试格式、数量、单文件和总大小限制 | 限制与配置一致，错误可理解；只有 complete 后为 active 的素材才算就绪，未完成素材不能提交。 |
| T5-04 | 模拟上传、complete、会话恢复失败，尝试重试或删除 | 失败素材状态清晰；可按对应阶段重试或删除，草稿不丢失；存储上传不携带业务认证或 Cookie。 |
| T5-05 | 测试最少实拍素材和线下交接 | 按配置执行最低数量及线下交接规则；未满足时不能进入有效报价或提交。 |
| T5-06 | 核对授权声明和制作须知；未勾选及刷新后再操作 | 未确认不能提交；显示服务端提供的文案和版本，刷新后按产品规则重新确认。 |
| T5-07 | 获取报价并修改规格；模拟价格隐藏、需人工报价、报价过期 | 金额、日期和规格以服务端结果为准；变更后重新报价；不能绕过人工核价或使用失效报价提交。 |
| T5-08 | 确认下单；模拟余额不足、明确拒绝、超时及重复点击 | 展示费用并二次确认；结果不明时保留原请求和幂等键；成功后进入正确订单，不能重复创建。 |
| T5-09 | 查看订单列表、详情、状态及交付 | 订单状态和计费状态分别正确；交付日期、逾期状态以服务端为准；刷新与分页正常，交付视频可播放下载。 |
| T5-10 | 分别模拟允许、不允许和已申请返工 | 依据服务端 `can_rework` 控制入口；申请和回复状态正确，不能擅自显示付费修改或重复申请。 |
| T5-11 | 分别模拟满足与不满足退款条件的订单 | 仅在服务端允许的条件下提供退款并二次确认；结果以服务端和钱包状态为准；不提供未经约定的普通自助取消。 |
| T5-12 | 从任务中心、项目管理、订单历史打开详情并切换空间 | 跳转到正确订单；分页不丢失已有记录；跨账号、跨空间不能看到无权访问的订单。 |

## 5. 执行命令与覆盖范围

在仓库根目录执行。以下用例使用模拟接口；先阅读用例断言，不能把文件名或退出码视作对整条业务链的证明。

```powershell
npm.cmd run typecheck
npm.cmd run test:e2e:typecheck
node.exe scripts/hooks/frontend-gate.mjs verify e2e/manual-delivery-visible.spec.ts e2e/manual-video.spec.ts e2e/promo-real.spec.ts e2e/promo-history-isolation.spec.ts e2e/project-management-refine.spec.ts e2e/project-management-promo.spec.ts e2e/promo-orders.spec.ts
# 查看输出目录中的截图，并核对实际交互断言后登记真实复核意见：
node.exe scripts/hooks/frontend-gate.mjs review <run-id> "填写已查看的画面和交互"
```

演示流程测试（如 `refine-demo.spec.ts`、`promo-demo.spec.ts`）只证明本地演示行为，不能替代真实流程或真实后端验证。生产构建、浏览器截图及异常处理的执行要求以 [前端修改后的浏览器验证规范](frontend-browser-verification.md) 为准；测试失败不得通过跳过用例或削弱断言掩盖。

## 6. 结果记录与验收

每个用例记录：编号、环境（mock / 真实）、账号和空间标识（脱敏）、步骤与测试数据、预期、实际结果、通过 / 失败 / 阻塞 / 未执行、截图或 trace、缺陷链接。界面截图和请求断言应共同证明流程，成功提交不等于真实交付完成。

验收报告至少包含：

- 已覆盖的页面、浏览器、视口和用例编号；mock 与真实后端分别列出。
- 失败、阻塞和未执行的用例、复现条件、影响及原因；已知问题不能标记为通过。
- 真实任务是否实际提交、交付、修改、取消或退款；未执行的费用操作明确写「未验证」。
- 关键截图、报告或 trace 路径，以及未检查的网络、权限和无障碍范围。

涉及本次改动的必测项全部通过、截图已实际复核、真实后端必测项有有效结果后，才可报告完整验收通过；受账号、费用或环境限制时按项目规范报告未通过及未验证范围。
