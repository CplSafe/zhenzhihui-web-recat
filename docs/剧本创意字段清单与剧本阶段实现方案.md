# 剧本创意字段清单与剧本阶段实现方案

整理日期：2026-11-05。本文用于字段盘点与方案评审，本次不修改业务代码。

## 1. 范围和依据

- 原型：`F:/工作文件/剧本创意C端原型.html` 的 `FIELDS`、`SPECS`、文件规则和交互；同时考虑本次会话里用户对必填和页面删减的明确要求。
- 前端：`src/views/ScriptIdeasView.tsx`、`src/views/ScriptPrototypeSections.tsx`、`src/views/ScriptFlowDemo.tsx`、`src/utils/scriptCardContent.ts`、`src/api/studentApplications.ts`。
- 后端：2026-11-05 从 `http://124.174.95.225:9000/swagger/doc.json` 读取的 Swagger 定义。文档描述并不等于已对具体账号或申请完成联调。
- 下列中文字段为业务字段；英文名称除明确注明是 Swagger 字段外，均为**建议名称**，需要前后端确认。
- 必填以原型字段定义与用户明确要求为准；“当前实现”描述真实业务页面，和浏览器本机演示分开。`—` 表示不适用或待确认。

## 2. 关键结论

1. 流程为：创作者入驻（账号资料，一次填写、可修改）→ 提交创意 → 一卡 → 剧本 → 完善剧本。每个阶段包含待提交、审核中、通过、退回等状态；是否允许撤回和重提以具体接口规则为准。
2. 最新 Swagger 的阶段提交枚举包含 `creative`、`card`、`script`、`final`，并兼容旧实例的 `draft`、`revision`。现有前端只把 `draft`、`script`、`revision` 接入待办编辑，**没有完整识别新 `card` 和 `final`**，所以四阶段在实际请求下尚不能视为完成。
3. Swagger 阶段提交只声明 `task_id`、`stage`、`content`，`content` 是最长 20000 字符的字符串；当前前端把字段编码进该字符串，不能据此宣称后端能单独检索或校验每个业务字段。
4. 原型四阶段均要求附件，真实页面当前无法上传；本机演示中的文件选择与真实附件提交不是同一能力。需要确认上传、归属、提交关联和下载契约。
5. Swagger 创建输入已有 `title`、`genre`（最大长度分别为 200 和 80），但当前 `FirstBody` 和提交函数没有把它们当独立属性提交，而是拼进 `creative`。前端应适配，实际服务行为待联调。
6. 独立“剧本”表单已有一部分前端代码，只有服务端返回 `script` 待办时才会进入；字段校验、附件、前后阶段转换、旧数据迁移以及真实服务端联调仍未完成。

| 身份类型 | 选择 | 是 | 选项以原型配置为准 |

| 擅长题材 | 可搜索多选 | 是 | 支持选已有题材及添加新题材 |

## 4. 提交创意字段

| 字段 | 类型 | 原型 / 用户要求 | 当前真实页面 |
| --- | --- | --- | --- |
| 申请人姓名 | 文本 | 必填，入驻后带入 | 可输入；随首次请求的 `name` 发送 |
| 学校 / 机构 | 文本 | 必填，入驻后带入 | 可输入；随 `school` 发送 |
| 联系电话 | 电话 | 当前真实流程必填 | 随 `phone` 发送；原型申请详情主要展示申请人和学校 |
| 剧名 | 文本 | 必填 | 前端校验；当前拼入 `creative` |
| 题材 | 可搜索 / 输入 | 必填 | 前端校验；当前拼入 `creative` |
| 剧情简介 / 故事创意 | 多行 | 必填 | 与剧名、题材等合并为 `creative` |
| 第一集剧本剧情 | 多行 | 选填 | 拼入 `creative` |
| 人物、身份、性格 | 多行 | 选填 | 拼入 `creative` |
| 剧本文档附件 | 多文件 | 必填 | 当前真实页面不可上传和关联，因此尚未满足必填要求 |

首次提交现有请求是 `name`、`phone`、`school`、`creative`，当前前端对姓名最多 80 字符、学校最多 200 字符、合并正文最多 12000 字符；这些是现有实现限制，具体后端校验以联调为准。原型简介提示 200～600 字，不应误认为已实现强制校验。

## 6. 剧本阶段字段和功能

| 页面字段 | 建议数据名 | 类型 | 必填 | 原型要求与待完成项 |
| --- | --- | --- | --- | --- |
| 中文剧名 | `title_zh` | 只读文本 | 是 | 继承前一阶段；当前可编辑，需统一 |
| 题材 | `genre` | 只读文本 | 是 | 继承创意；当前可编辑，需统一 |
| 预计集数 | `planned_episodes` | 整数 | 是 | 原型 1～200，默认 55；当前只设置最小值 1 |
| 单集最短时长 | `duration_min_seconds` | 整数 | 是 | 原型 10～600 秒，默认 65；两个值共同组成单集时长 |
| 单集最长时长 | `duration_max_seconds` | 整数 | 是 | 原型 10～600 秒，默认 72；不得小于最短时长；当前缺范围和交叉校验 |
| 首个付费解锁集 | `first_paid_episode` | 整数 | 是 | 原型 1～200，默认第 10 集；不得超过预计集数是否强制待确认 |
| 重点付费 / 追更节点 | `paywall_node_count` | 整数 | 否 | 原型 0～30 个，默认 11；当前数值输入设置最小值 1，不能填写 0；字段具体业务含义待确认 |

| 世界观与核心规则 | `world_rules` | 多行 | 否 | 现实题材可写“不适用” |
| 完整剧本文档附件 | `attachments` | 多文件 | 是 | 真实上传、存储、绑定、下载待接入 |

剧本填写规范还要求文档包含中英文剧名、系列总名、题材与核心类型、总时长、付费规划、三版简介、人物全档、分幕大纲、分集正文和中英对白等。**原型把这些放在模板说明中，不代表当前网页有对应独立输入字段**。是否将它们进一步结构化应另行确认。

当前代码的限制：只有收到 `current_task.stage === 'script'` 才显示剧本输入表单；有的旧任务可能返回的是前一阶段正文，此时预填转换、旧格式保护需专门测试。新字段编码到 `content` 字符串，审核页按编码解析；服务端是否接受该格式、审核端如何阅读、字符限制和跨端兼容均未真实验证。可编辑期间的长文本、上传状态、离开恢复、轮询冲突和重试需要明确实现。

## 8. 附件、审批与列表数据

原型每阶段文件规则为最多 30 个、每个最大 500 MB，选择器限制 `.doc`、`.docx`、`.pdf`、`.txt`、`.md`、`.ppt`、`.pptx`。需确认文件数量按阶段还是按版本计算，及格式校验、上传进度、删除、下载、重试、跨账号权限、历史版本留存；切勿仅保存文件名并显示成上传成功。

审批 / 版本数据至少需要：申请 ID、阶段码、任务 ID、阶段状态、当前待办、版本号、正文 / 字段快照、附件引用、提交时间、审核节点、审核结果、审核意见、审核时间、审核与版本关联。Swagger 的 `Progress` 已描述 `current_stage`、`current_task`、`flow_version`、`review_status`、`stage_statuses`、`reviews`、`versions`；是否每条记录完整提供以联调为准。

“我的创意”需核对：已提交、审核中、需修改、已通过四项统计；关键字、阶段、状态、题材筛选；列表中的剧名、题材、当前阶段、审核状态、创建时间、操作。当前前端仍需核对筛选参数、统计接口和真实返回；不能将单页过滤数量冒充全量统计。

入驻资料、撤回 / 取消、附件上传、已通过阶段修改重提与旧实例迁移，需分别确认最新接口及可执行动作；不应根据接口名猜测状态变化。Swagger 描述四阶段，但尚未在本次对具体申请做真实提交和状态流转验证。

## 10. 剧本阶段实施方案（本次不实施）

1. **对齐阶段与状态**：集中规范新 `creative/card/script/final` 和旧 `draft/revision`；按 `flow_version`、实际待办及 `stage_statuses` 显示当前和已完成步骤。旧 `revision` 不能凭空推断为存在独立剧本待办。
2. **补齐表单和继承**：复用现有字段配置及控件，补齐剧名、题材继承，范围输入、计数器、必填提示、模板和附件；覆盖桌面与窄屏。
3. **实现有效校验**：按确认后的数值边界、时长大小关系、必填和附件规则验证；显示缺少什么；保留用户输入，避免仅靠 HTML 输入属性。
4. **统一数据契约**：优先采用经双方确认的结构化请求和附件 ID；若暂用 `content` 字符串，需要明确可读格式、版本标识、长度、后台审核端可读性及旧文本兼容。保留原文，避免跨阶段将 JSON 暴露给用户或覆盖先前数据。
5. **接入交互与恢复**：待提交 → 提交中 → 审核中 → 通过 / 退回；使用实际任务 ID、阶段及幂等键；断网或结果不确定时可查询及安全重试；轮询改变待办时保留编辑内容；有撤回接口后再实现撤回。
6. **附件和历史**：对接真实上传与版本关联；记录文件 ID / 名称 / 大小，处理失败、删除、权限、过期下载及刷新恢复。没有接口时明确展示不可用，不能伪造成功。
7. **验证**：覆盖阶段映射、新旧实例、必填和边界、上传失败、提交及重试、审核展示、退回、刷新、桌面和窄屏；先模拟接口，再使用授权测试数据联调真实后端。每条结果区分模拟与真实，输出验收记录。
