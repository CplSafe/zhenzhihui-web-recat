# 剧本创意后端联调清单

整理日期：2026-11-09。依据当前前端实现整理；接口被前端调用不代表线上后端已支持。优先处理创作者入驻，其余接口请后端核对当前实现与下列契约的差异。原《剧本创意后端对接需求》中的旧字段和接口现状有过时内容，以本清单及双方确认的契约为准。

## 一、优先：创作者入驻资料

前端调用 `GET /api/v1/script-creators/me` 查询，`PUT /api/v1/script-creators/me` 保存，使用当前登录态确定账号，JSON 响应外层为 `{ "code": 0, "message": "", "data": { ... } }`。请后端确认下列字段的数据库、校验、读写、同步及回显均已支持。

| 字段 | 类型 / 取值 | 要求 |
| --- | --- | --- |
| `student_status` | string：`student`、`graduated` | 新增；必填，分别表示在校学生、已毕业 |
| `creator_type` | string：`creator`、`team`、`freelancer` | 新增；必填，分别表示自然流创作者、团队编剧、自由职业；独立于学生状态 |
| `province` | string | 新增；必填，省、直辖市或地区名称 |
| `city` | string | 已有字段调整为必填的城市名称，与省份分别存储 |
| `school` | string | 在校：学校全称必填；已毕业：机构 / 公司选填，允许空字符串 |
| `grade_major` | string | 在校选填；已毕业时前端提交空字符串 |
| `identity_type` | string | 历史兼容字段；前端暂时在校传 `student`，毕业传对应 `creator_type`。不能依靠它还原两个维度 |
| `real_name`、`phone`、`email` | string | 必填 |
| `contact_im` | string | 微信 / QQ，选填 |
| `specialties` | string[] | 擅长题材，前端校验 1～10 个且不重复 |
| `agreement_accepted` | boolean | PUT 必须为 `true`，请记录同意行为 |
| `agreement_version` | string | PUT 提交 GET 返回的协议版本；请核对版本并记录同意时使用的版本与时间 |

PUT 请求示例（字段均为当前前端发送）：

```json
{
  "real_name": "张三",
  "identity_type": "student",
  "student_status": "student",
  "creator_type": "freelancer",
  "school": "某某大学",
  "grade_major": "大二 / 编剧",
  "province": "山东省",
  "city": "济宁市",
  "phone": "13800001111",
  "email": "example@example.com",
  "contact_im": "",
  "specialties": ["悬疑", "都市"],
  "agreement_accepted": true,
  "agreement_version": "后端返回的协议版本"
}
```

GET 与 PUT 的 `data` 均需包含 `profile`、`agreement_version`、`originality_version`、`workflow_synced`。资料不存在时请明确约定 `profile: null` 和协议版本；PUT 成功后 `profile` 需回显已保存字段，尤其是 `student_status`、`creator_type`、`school`、`grade_major`、`province`、`city`。前端会逐项核对这些值：未回显或值不一致会提示可能部分保存；`workflow_synced` 为 `false` 时不会显示完成，且无法提交新创意。建议后端保证原子保存或明确部分成功的语义和恢复方式。

旧数据兼容：`identity_type=student` 只能推断在校，不能推断创作身份；其他旧身份也不能可靠推断学生状态。旧 `city` 可能是“山东 · 济宁”等自由文本，前端会保留原值提示用户重新选择，后端应保留旧值并提供迁移策略，避免直接统计为标准市名。前端支持“其他地区 / 城市”手填，后端不要只接受固定名单；建议后续统一维护地区代码和目录，地区变更及港澳台统计口径需双方确认。

**需要联动确认：**新建创意页面已移除申请人信息输入，前端从当前入驻资料带入申请人快照；已毕业时允许 `applicant_school` 为空。请后端确认并取消该场景的学校必填约束，并约定快照如何表达学生状态、创作身份和学校 / 机构；真实接口尚未联调。

**协议版本：**本次提供的协议与旧正文均标记 `2026-11-06`，但内容不同。请确认新的唯一版本标识、历史同意记录与协议文本的对应关系；前端展示静态协议正文，版本值来自后端，双方应保证一致。

## 二、创意与阶段接口：请核对现有能力

以下是前端当前调用和字段，不代表需要重复新增接口；请确认接口支持、权限、状态流转和老版本兼容。

| 方法与路径 | 前端使用 |
| --- | --- |
| `POST /api/v1/student-applications` | 首次提交，发送结构化 `data` 与附件引用 |
| `GET /api/v1/student-applications` | 查询 `limit`、`offset`，可带 `q`、`stage`、`review_status`、`genre`；返回 `items`、`total`、可选 `stats` |
| `GET /api/v1/student-applications/{id}` | 返回 `application`、`progress_available` 和 `workflow` |
| `POST /api/v1/student-applications/{id}/stages` | 提交 `task_id`、`stage`，新流程发送 `data`，旧流程发送 `content` |
| `POST /api/v1/student-applications/{id}/withdraw` | 提交 `task_id`、`reason` 撤回 |

首次提交 `data`：`applicant_name`、`applicant_phone`、`applicant_school`、`title`、`genre`、`synopsis`、`episode_1_plot`、`characters`、`attachments`。阶段 `data` 主要字段：

- 创意：与首次提交相同；附件为 `[{"file_id": 123}]`。
- 一卡：`title_zh`、`title_en`、`covered_episodes`、`strongest_paywall_episode`、`synopsis_zh_full`、`selling_points`、`character_bios`、`episode_outline_and_paywalls`、`attachments`；前端要求覆盖集数至少 8。
- 剧本：`title_zh`、`genre`、`planned_episodes`、`duration_min_seconds`、`duration_max_seconds`、`first_paid_episode`、`paywall_episodes`（整数数组）、`act_outline`、`world_rules`、`attachments`。`flow_version >= 5` 时还提交 `originality_confirmed: true`、`originality_version`。
- 完善 / 修订：`revision_description`、`originality_confirmed: true`、`originality_version`、`attachments`。

详情请返回当前任务、阶段、状态、可撤回权限、版本和审核意见，并确认 `structured`、`flow_version`、历史附件和可编辑数据的返回。前端以 `structured === true` 或 `flow_version >= 4` 判断结构化流程；旧流程继续使用 `content`。创建、阶段提交、撤回使用 `X-Idempotency-Key`，请明确重复请求、不同请求体冲突、有效期与错误码。

## 三、附件接口

前端调用 `POST /api/v1/script-files/uploads` 获取上传凭证（请求 `file_name`、`file_size`，携带幂等键），响应包含 `file`、`url`、`form_fields`、`upload_required`；需要上传时浏览器直传，随后调用 `POST /api/v1/script-files/{id}/complete`。完成接口返回 409 时前端会调用 `GET /api/v1/script-files/{id}` 确认状态；只有 `status: ready` 的文件可关联提交。删除使用 `DELETE /api/v1/script-files/{id}`。

请确认文件归属校验、历史版本引用、重试和大小 / 格式限制，以及失败、删除与下载的处理。前端当前限制每次提交 1～30 个文件、单个不超过 500 MiB；请对齐服务端实际规则。
